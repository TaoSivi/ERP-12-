# LaoBooks ERP

ERP ສຳລັບ SME ລາວ — ບັນຊີຄູ່, Invoice/Bill/PO, ສາງ (FIFO), POS, ເງິນເດືອນ (PIT/LSSO), ຊັບສິນຖາວອນ, ງົບປະມານ, ລາຍງານ.
ເປັນເວັບ static (HTML + JS) ບໍ່ຕ້ອງ build.

## ເປີດໃຊ້ງານ (Demo Mode)

```bash
npm run serve        # ຫຼື: python -m http.server 8123
```

ເປີດ http://localhost:8123 — ຂໍ້ມູນເກັບໃນ `localStorage` ຂອງ browser (ມີຂໍ້ມູນຕົວຢ່າງ).

## ໂຄງສ້າງ

| ໄຟລ໌ | ໜ້າທີ່ |
|---|---|
| `index.html` | ໂຄງໜ້າເວັບ + ໂຫຼດ script ຕາມລຳດັບ |
| `css/styles.css` | ສະໄຕລ໌ |
| `js/config.js` | ຕັ້ງຄ່າ (`APPS_SCRIPT_URL`, ຂໍ້ມູນບໍລິສັດເລີ່ມຕົ້ນ) |
| `js/store.js` | ຖານຂໍ້ມູນ (localStorage ຫຼື Google Sheet) |
| `js/accounting.js` | ເຄື່ອງຈັກບັນຊີ: journal, VAT, FIFO, void, ປິດປີ |
| `js/guard.js` | ດ່ານກວດກ່ອນ Post + precedents |
| `js/autopost.js` | ບັນທຶກອັດຕະໂນມັດຕາມເວລາ (ຄ່າເສື່ອມ, ລ່ວງໜ້າ, recurring) |
| `js/flows.js` | ຂັ້ນອະນຸມັດຕາມວົງເງິນ + ເງິນສຳຮອງ / ເຄລຍ / ຂໍເບີກຈ່າຍ |
| `js/checks.js` | ຈັບຄູ່ທະນາຄານ + ກວດຄວາມຜິດປົກກະຕິ |
| `js/procure.js` | ຂະບວນການຈັດຊື້: ຂັ້ນຕອນ, ສິດ, ການລົງບັນຊີ |
| `js/procure-ui.js` | ໜ້າຈໍຈັດຊື້ |
| `js/flows-ui.js` | ໜ້າຈໍຄຳຂໍ & ອະນຸມັດ + ຕັ້ງຂັ້ນອະນຸມັດ |
| `js/ui.js` | modal, toast, table |
| `js/app.js` | router + ໜ້າຈໍທັງໝົດ |
| `tests/` | test ຂອງ `accounting.js` |

ລຳດັບໂຫຼດ script ສຳຄັນ: `config → store → accounting → guard → autopost → flows → checks → procure → ui → procure-ui → flows-ui → app`.
ທຸກໄຟລ໌ໃນ `index.html` ມີ `?v=` — **ປ່ຽນເລກທຸກຄັ້ງທີ່ອອກເວີຊັນໃໝ່** ເພື່ອໃຫ້ browser ໂຫຼດໂຄດໃໝ່.

## Test

```bash
npm test
```

ໃຊ້ `node:test` (Node 20+). Test ໂຫຼດໄຟລ໌ຈິງ `config/store/accounting` ເຂົ້າ sandbox, ບໍ່ຕ້ອງຕິດຕັ້ງຫຍັງ. ຄຸ້ມຄອງ: journal ສົມດຸນ, Invoice/Bill/Payment, FIFO, void, ປິດປີ, ແລະ **ການລັອກງວດບັນຊີ**.

## ລັອກງວດບັນຊີ

ຕັ້ງ "ວັນລັອກບັນຊີ" ໃນ ຕັ້ງຄ່າ → ຫ້າມ post ເອກະສານທີ່ມີວັນທີ ≤ ວັນນັ້ນ.
ທຸກ function ທີ່ post ບັນຊີເອີ້ນ `Acc.assertOpen(date)` ທັນທີທີ່ເລີ່ມ, ກ່ອນຂຽນ payment / ເຄື່ອນໄຫວສາງ — ຖ້າງວດຖືກລັອກ ຈະບໍ່ມີຂໍ້ມູນຄ້າງ.
ການ void ເອກະສານໃນງວດທີ່ລັອກ ຈະບັນທຶກ journal ຍົກເລີກໃນວັນທີປັດຈຸບັນ.
ໝາຍເຫດ: ການປິດສິ້ນປີ (`yearEndClose`) ຍັງບໍ່ຕັ້ງວັນລັອກໃຫ້ອັດຕະໂນມັດ — ຕ້ອງຕັ້ງເອງຫຼັງປິດປີ.

## ໂໝດຂັ້ນສູງ

ຄ່າເລີ່ມຕົ້ນເຊື່ອງ ເມນູ **ເອກະສານ (DMS)** ແລະປຸ່ມບັນຊີຂັ້ນສູງ (ECL, NRV, Impairment, Landed Cost, FX Adjust, Job Costing, Retention, BOM).
ເປີດໄດ້ທີ່ ຕັ້ງຄ່າ → "ໂໝດຂັ້ນສູງ".

## ດ່ານກວດກ່ອນ Post (Guard)

ກ່ອນ Post Invoice, Bill, Journal ມື, Quick Record ແລະ Quick Expense, `js/guard.js` ກວດຄວາມຜິດພາດທີ່ຄົນມັກເຮັດ:

| ກົດ | ລະດັບ | ກວດຫຍັງ |
|---|---|---|
| `DUPLICATE` | 🛑 ຕ້ອງ Manager | ຄູ່ຄ້າ + ຍອດ + ວັນທີ (±7 ວັນ) ຄືກັບເອກະສານທີ່ Post ແລ້ວ |
| `JE_MEMO` | 🛑 ຕ້ອງ Manager | Journal ມືບໍ່ມີຄຳອະທິບາຍ |
| `JE_LARGE` | 🛑 ຕ້ອງ Manager | Journal ມືເກີນ `approval_limit` |
| `UNUSUAL_AMOUNT` | ⚠️ ເຕືອນ | ຍອດສູງກວ່າສະເລ່ຍຂອງຄູ່ຄ້າ > 3 ເທົ່າ (ມີປະຫວັດ ≥ 3 ໃບ) |
| `BELOW_COST` | ⚠️ ເຕືອນ | ຂາຍຕ່ຳກວ່າຕົ້ນທຶນ |
| `ACCOUNT_TYPE` | ⚠️ ເຕືອນ | ຄ່າໃຊ້ຈ່າຍລົງບັນຊີ Revenue/Equity |
| `JE_CONTROL` / `JE_CASH` | ⚠️ ເຕືອນ | ແກ້ບັນຊີຄຸມ (AR/AP/ສາງ/VAT) ຫຼືບັນຊີທະນາຄານດ້ວຍມື |
| `DATE_FUTURE` / `DATE_OLD` | ⚠️ ເຕືອນ | ວັນທີໃນອະນາຄົດ ຫຼືຍ້ອນຫຼັງ > 60 ວັນ |

- **⚠️ ເຕືອນ**: ພະນັກງານຢືນຢັນໄດ້ ຖ້າໃຫ້ເຫດຜົນ (≥ 5 ຕົວອັກສອນ). ບັນທຶກໃນ Guard Log ເປັນ "ລໍຖ້າທົບທວນ".
- **🛑 ຕ້ອງ Manager**: ສະເພາະ Manager/Admin ເທົ່ານັ້ນທີ່ຢືນຢັນໄດ້.
- **Precedent**: ເຫດຜົນທີ່ **Manager/Admin** ຢືນຢັນ ຈະຖືກຈື່ (ກົດ + ລູກຄ້າ/ບັນຊີ/ສິນຄ້າດຽວກັນ). ຄັ້ງຕໍ່ໄປຜ່ານອັດຕະໂນມັດ ແລະບັນທຶກ log. `DUPLICATE`, `JE_MEMO`, `JE_LARGE` ຖືກຕັ້ງໃຫ້ **ບໍ່ຈື່** (precedent ຜ່ານບໍ່ໄດ້).
- ເຫດຜົນຂອງພະນັກງານທົ່ວໄປ **ບໍ່** ກາຍເປັນ precedent.
- ເບິ່ງ/ລຶບ precedent ແລະ log ໄດ້ທີ່ ຕັ້ງຄ່າ → 🛡 Guard Log.
- ຈຸດຕໍ່ AI: `Guard.review()` ແມ່ນຈຸດທີ່ຈະສຽບ Claude ເຂົ້າມາຕອນມີ backend (ໃຫ້ AI ກວດເພີ່ມ ແລະໃຊ້ precedents ເປັນບໍລິບົດ).

ໝາຍເຫດ: ບົດບາດຍັງເປັນຂອງ browser (ບໍ່ມີ login ຈິງ) ດັ່ງນັ້ນ "ຕ້ອງ Manager" ເປັນພຽງການຂັດຂວາງ ບໍ່ແມ່ນຄວາມປອດໄພຈົນກວ່າຈະມີ login. Cloud Mode ຕ້ອງເພີ່ມ sheet `precedents`, `guard_log`, `auto_runs`, `pr_quotes`, `approvals`, `grns`, `grn_lines`, `requests`, `request_lines`, `accruals` ໃນ Apps Script.

## Auto-Posting (ບັນທຶກບັນຊີຕາມເວລາ)

`js/autopost.js` ບັນທຶກລາຍການປະຈຳທີ່ອະນຸມັດ/ຕັ້ງຄ່າແລ້ວໃຫ້ເອງ ຕອນເປີດໂປຣແກຣມ (ຕັ້ງຄ່າ → ⏱ Auto-Posting):

| ປະເພດ | ບັນທຶກຫຍັງ | ວັນທີ |
|---|---|---|
| `DEPR` | ຄ່າເສື່ອມຊັບສິນ (ເລີ່ມນັບຈາກເດືອນທີ່ໄດ້ມາ, ບໍ່ເກີນຕົ້ນທຶນ) | ທ້າຍເດືອນ |
| `PREPAID` | ຕັດຄ່າໃຊ້ຈ່າຍລ່ວງໜ້າ (ນັບຈາກເດືອນ "ນຳເຂົ້າ") | ທ້າຍເດືອນ |
| `DEFERRED` | ຮັບຮອງລາຍຮັບລ່ວງໜ້າ | ທ້າຍເດືອນ |
| `REC_JE` / `REC_INV` | Recurring JE / Invoice ທີ່ຕັ້ງ "auto" | ວັນທີ່ກຳນົດຂອງເດືອນ |
| `ACCRUAL` | ຄ່າໃຊ້ຈ່າຍຄ້າງຈ່າຍປະຈຳເດືອນ (Dr ຄ່າໃຊ້ຈ່າຍ · Cr 2160) + ກັບລາຍການໃຫ້ເອງ | ທ້າຍເດືອນ / ວັນທີ 1 |
| `VAT_CLOSE` (ເລືອກເປີດ) | ໂອນ VAT ຂາຍ − VAT ຊື້ ຂອງເດືອນ ເຂົ້າ VAT ຕ້ອງຍື່ນ (2250) | ທ້າຍເດືອນ |
| `PTAX` (ເລືອກເປີດ) | ສຳຮອງອາກອນກຳໄລ = ກຳໄລສະສົມປີ × % − ທີ່ຕັ້ງແລ້ວ | ທ້າຍເດືອນ |
| ລັອກງວດອັດຕະໂນມັດ (ເລືອກເປີດ) | N ວັນຫຼັງທ້າຍເດືອນ ລັອກເດືອນນັ້ນ — ຖ້າບໍ່ມີລາຍການຜິດພາດ/ຄ້າງ | — |

ກົດຄວາມປອດໄພ:
- **ບັນທຶກໄດ້ເທື່ອດຽວຕໍ່ງວດ**: ທຸກລາຍການຂຽນ `auto_runs` (key `TYPE:ref:YYYY-MM`). ປຸ່ມກົດເອງ (Run ຄ່າເສື່ອມ, ຕັດງວດ, ສ້າງ JE/Invoice ຊ້ຳ) ໃຊ້ ledger ດຽວກັນ ຈຶ່ງກົດຊ້ຳບໍ່ໄດ້ ແລະບໍ່ຊ້ຳກັບທີ່ລະບົບຈະບັນທຶກທ້າຍເດືອນ.
- **ບໍ່ບັນທຶກຍ້ອນຫຼັງ**: ບໍ່ແຕະງວດກ່ອນ "ງວດເລີ່ມຕົ້ນ" (ຄ່າເລີ່ມ = ເດືອນທີ່ເປີດໃຊ້). ເບິ່ງ preview ກ່ອນກົດ ▶ ແລ່ນດຽວນີ້.
- **ເຄົາລົບການລັອກງວດ**: ງວດທີ່ລັອກຖືກຂ້າມ ແລະສະແດງໃນລາຍການ.
- **ຜິດພາດຢ່າງໜຶ່ງບໍ່ຢຸດທັງໝົດ**: ລາຍການທີ່ຜິດພາດຖືກລາຍງານ ແລະລອງໃໝ່ຄັ້ງຕໍ່ໄປ, ບໍ່ຄ້າງ Invoice ເຄິ່ງໆກາງ.
- ສະເພາະ Manager/Admin ເປີດ/ປິດໄດ້. ເມື່ອປິດ ລະບົບຈະບໍ່ບັນທຶກຫຍັງເອງ.

ຂໍ້ຈຳກັດ: ແອັບ static ບໍ່ມີ scheduler ຈິງ — ບັນທຶກເມື່ອມີຄົນເປີດໂປຣແກຣມ. ຖ້າສອງຄົນເປີດພ້ອມກັນໃນ Cloud Mode ອາດບັນທຶກຊ້ຳ ຈົນກວ່າ backend ຈະມີ lock/trigger. ເມື່ອມີ backend ໃຫ້ຍ້າຍ `Autopost.run()` ໄປຮັນດ້ວຍ time-trigger. ການບັນທຶກທີ່ເຮັດກ່ອນເປີດ Auto-Posting (ກົດເອງແບບເກົ່າ) ບໍ່ມີ key ໃນ ledger — ຕັ້ງ "ງວດເລີ່ມຕົ້ນ" ໃຫ້ຫຼັງງວດທີ່ເຮັດເອງແລ້ວ.

## ຈັດຊື້ຄົບວົງຈອນ (Procure-to-Pay)

ເມນູ **📋 ຈັດຊື້ (ຂໍ → ຈ່າຍ)**. ໃບຂໍຊື້ໜຶ່ງໃບຖືໄປຕັ້ງແຕ່ຕົ້ນຈົນຈົບ (`js/procure.js` ຕັກກະ, `js/procure-ui.js` ໜ້າຈໍ):

| # | ຂັ້ນ | ໃຜເຮັດ | ລົງບັນຊີ |
|---|---|---|---|
| 1 | ຂໍຊື້ → ສົ່ງຂໍອະນຸມັດ | ທຸກບົດບາດ | ບໍ່ລົງ |
| 2 | ອະນຸມັດຂໍຊື້ (ອະນຸມັດ / ສົ່ງຄືນແກ້ / ປະຕິເສດ) | Manager, Admin | ບໍ່ລົງ |
| 3 | ເກັບໃບສະເໜີລາຄາ → ສ້າງ PO | Purchasing, Manager, Admin | ບໍ່ລົງ |
| 4 | ອະນຸມັດ PO (ເກີນ `approval_limit` → Admin ເທົ່ານັ້ນ) | Manager, Admin | ບໍ່ລົງ (ພຽງຂໍ້ຜູກມັດ) |
| 5 | ຮັບເຄື່ອງ (ຮັບບາງສ່ວນໄດ້) | Warehouse, Purchasing, Manager, Admin | **Dr ສິນຄ້າ / ຄ່າໃຊ້ຈ່າຍ / ຊັບສິນ · Cr GR/IR (1500)** |
| 6 | ບິນຜູ້ສະໜອງ (3-way match) | Accountant, Manager, Admin | **Dr GR/IR + VAT · Cr ເຈົ້າໜີ້** |
| 7 | ຈ່າຍເງິນ | Accountant, Cashier, Manager, Admin | **Dr ເຈົ້າໜີ້ · Cr ທະນາຄານ** |

ເປັນຫຍັງລົງບັນຊີຕອນຮັບເຄື່ອງ (ບໍ່ແມ່ນລໍຖ້າຕອນຈ່າຍ): ເມື່ອເຄື່ອງເຂົ້າມາ ບໍລິສັດມີສິນຄ້າ/ຊັບສິນ ແລະ ມີໜີ້ແລ້ວ ເຖິງວ່າບິນຍັງບໍ່ມາ. GR/IR ເປັນຂົວລະຫວ່າງ "ຮັບເຄື່ອງ" ກັບ "ບິນ" — ຍອດຄ້າງໃນ GR/IR = ຮັບແລ້ວແຕ່ຍັງບໍ່ໄດ້ບິນ.

ກົດ:
- **ແຍກໜ້າທີ່**: ບົດບາດທີ່ຍື່ນຂໍ/ສ້າງ PO ອະນຸມັດເອງບໍ່ໄດ້ (ຍົກເວັ້ນ Admin).
- **ໃບສະເໜີລາຄາ**: ຍອດ ≥ 10,000,000 ₭ ຕ້ອງມີ 3 ໃບ; ຖ້າບໍ່ຄົບ ຫຼື ບໍ່ເລືອກລາຄາຖືກສຸດ ຕ້ອງໃສ່ເຫດຜົນ (ບັນທຶກໃນປະຫວັດ). ຕັ້ງໄດ້ໃນ settings `procure` (`quote_threshold`, `min_quotes`, `price_tolerance`).
- **ຮັບເກີນຈຳນວນສັ່ງ** ບໍ່ໄດ້. "ປິດການຮັບ" ເມື່ອຜູ້ສະໜອງສົ່ງບໍ່ຄົບ.
- **3-way match** (PO · ຮັບເຄື່ອງ · ບິນ): ບິນເກີນຈຳນວນທີ່ຮັບ ຫຼື ລາຄາຕ່າງຈາກ PO > 2% → Guard ຂັດ ໃຫ້ Manager/Admin ຢືນຢັນ.
- **ຊັບສິນຖາວອນ** ທີ່ຊື້ ຖືກລົງທະບຽນເອງຕອນຮັບເຄື່ອງ (ອາຍຸ 60 ເດືອນ) ແລ້ວ Auto-Posting ຄິດຄ່າເສື່ອມໃຫ້.
- ຍອດສະເໜີຖືກແບ່ງລົງແຕ່ລະແຖວເປັນ **ຈຳນວນເຕັມກີບ**; ບິນໃສ່ເປັນຍອດເງິນຕໍ່ແຖວ ຕາມບິນຜູ້ສະໜອງ.

## ຄຳຂໍ & ອະນຸມັດ (ເງິນສຳຮອງ · ເຄລຍ · ຂໍເບີກຈ່າຍ)

ເມນູ **✍️ ຄຳຂໍ & ອະນຸມັດ** (`js/flows.js`, `js/flows-ui.js`). ອະນຸມັດຄົບແລ້ວ ລະບົບລົງບັນຊີໃຫ້ເອງ:

| ປະເພດ | ຂັ້ນຕອນ | ລົງບັນຊີອັດຕະໂນມັດ |
|---|---|---|
| ເບີກເງິນສຳຮອງ (ADV) | ຂໍ → ອະນຸມັດ → ແຄຊຽຈ່າຍ → ລໍເຄລຍ | ຈ່າຍ: Dr ເງິນສຳຮອງພະນັກງານ (1450) · Cr ເງິນສົດ |
| ເຄລຍເງິນສຳຮອງ (CLR) | ຍື່ນໃບບິນ → ອະນຸມັດ → ຄືນ/ຈ່າຍເພີ່ມ | Dr ຄ່າໃຊ້ຈ່າຍ + VAT · Cr 1450; ໃຊ້ບໍ່ໝົດ Dr ເງິນສົດ · Cr 1450; ໃຊ້ເກີນ Cr ຄ້າງຈ່າຍພະນັກງານ (2150) ແລ້ວຈ່າຍ |
| ຂໍເບີກຈ່າຍ (PAY) ຜູ້ສະໜອງ | ຂໍ → ອະນຸມັດ → ຈ່າຍ | ອະນຸມັດ: ສ້າງ Bill (Dr ຄ່າໃຊ້ຈ່າຍ + VAT · Cr ເຈົ້າໜີ້) · ຈ່າຍ: Dr ເຈົ້າໜີ້ · Cr ທະນາຄານ |
| ຂໍເບີກຈ່າຍ (PAY) ເບີກຄືນພະນັກງານ | ຂໍ → ອະນຸມັດ → ຈ່າຍ | Dr ຄ່າໃຊ້ຈ່າຍ + VAT · Cr 2150 → ຈ່າຍ |

- ທຸກລາຍການຕ້ອງມີ **ເລກທີ່ໃບບິນ**. ໝາຍ VAT ຖ້າໃບບິນລວມ VAT 10% — ລະບົບແຍກ VAT ຊື້ໃຫ້ເອງ.
- ເງິນສຳຮອງຕ້ອງເຄລຍພາຍໃນ **15 ວັນ** (ປ່ຽນໄດ້). ຖ້າມີໃບຄ້າງເກີນກຳນົດ **ເບີກໃໝ່ບໍ່ໄດ້**.
- ເຕືອນຜູ້ອະນຸມັດເມື່ອຄົນດຽວກັນຍື່ນຫຼາຍໃບພາຍໃນ 3 ວັນ ລວມເກີນວົງເງິນຂັ້ນທຳອິດ (ອາດແບ່ງຍອດ).

## ຂັ້ນອະນຸມັດຕາມວົງເງິນ

ຕັ້ງຄ່າ → **✍️ ຂັ້ນອະນຸມັດ** (Admin). ໃຊ້ກັບ ໃບຂໍຊື້ ແລະ ທຸກຄຳຂໍ. ຄ່າເລີ່ມຕົ້ນ:

| ວົງເງິນ | ຂັ້ນອະນຸມັດ |
|---|---|
| ≤ 5,000,000 ₭ | Manager |
| ≤ 20,000,000 ₭ | Manager → Accountant |
| > 20,000,000 ₭ | Manager → Accountant → Admin |

ກົດ: ຜູ້ຂໍອະນຸມັດເອງບໍ່ໄດ້ · ແຕ່ລະບົດບາດອະນຸມັດໄດ້ຂັ້ນດຽວ (ລວມ Admin) · Admin ແທນບົດບາດທີ່ຂາດໄດ້.
ໃບຂໍຊື້ສະແດງ **ງົບປະມານ**: ງົບ, ໃຊ້ແລ້ວ, ຜູກມັດ (ໃບຂໍຊື້ອື່ນທີ່ຍັງເປີດ), ຂໍນີ້ → ເຫຼືອ/ເກີນ (ເຕືອນ, ບໍ່ຂັດ).

## ອະນຸມັດ = ລົງບັນຊີ

- **Invoice / Bill** ທີ່ເກີນ `approval_limit`: ກົດ "✅ ອະນຸມັດ & ລົງບັນຊີ" ຄັ້ງດຽວ (ຜ່ານ Guard ກ່ອນ).
- **ເງິນເດືອນ**: HR ຄິດ → ສົ່ງຂໍອະນຸມັດ → Manager/Admin ອະນຸມັດ = ລົງບັນຊີ. ຜູ້ຄິດອະນຸມັດເອງບໍ່ໄດ້ (ຍົກເວັ້ນ Admin).

## ກວດຄວບຄຸມ (`js/checks.js`)

- **ຈັບຄູ່ທະນາຄານ**: ທຽບກັບບັນຊີທະນາຄານໃນບັນຊີແຍກປະເພດ (ທຸກການເຄື່ອນໄຫວ ບໍ່ສະເພາະ payment) — ຍອດ + ວັນທີ ± 3 ວັນ + ເລກອ້າງອີງ, ໜຶ່ງຕໍ່ໜຶ່ງ. ລາຍການທີ່ມີແຕ່ຝັ່ງທະນາຄານ: ກົດ "ລົງເປັນຄ່າທຳນຽມ" / "ລົງເປັນລາຍຮັບອື່ນ".
- **ກວດຄວາມຜິດປົກກະຕິ** (ລາຍງານ → 🔎): ຜູ້ສະໜອງ/ລູກຄ້າຊ້ຳ, ບິນແບ່ງຫຼົບວົງເງິນ, Journal ມືຍອດກົມ/ວັນອາທິດ/ຍ້ອນຫຼັງ > 30 ວັນ, ລາຍການທະນາຄານຄ້າງ > 30 ວັນ, ເງິນສຳຮອງເກີນກຳນົດ, ຄຳເຕືອນທີ່ລໍທົບທວນ.

## ທິດທາງ UI (Action-first)

- ທຸກໜ້າມີ **ການກະທຳຫຼັກອັນດຽວ** (ປຸ່ມໃຫຍ່). ສະຖານະທີ່ "ລໍຄົນອື່ນ" ສະແດງເປັນກ່ອງເສັ້ນປະ ພ້ອມບອກວ່າລໍໃຜ.
- ໜ້າຫຼັກເລີ່ມດ້ວຍ **"ສິ່ງທີ່ຕ້ອງເຮັດມື້ນີ້"**: ຈັດຊື້ລໍທ່ານ, ເອກະສານລໍອະນຸມັດ, ລູກຄ້າຄ້າງເກີນກຳນົດ, ບິນໃກ້ຮອດກຳນົດ, ລາຍການອັດຕະໂນມັດ, ຄຳເຕືອນທີ່ລໍທົບທວນ, ສິນຄ້າໃກ້ໝົດ — ແຕ່ລະອັນມີປຸ່ມໄປເຮັດທັນທີ.
- ຟອມເຮັດວຽກໃນໜ້າ (inline) ແທນການເປີດໜ້າຕ່າງຊ້ອນກັນ. Component: `.next-box`, `.ac-card`, `.stepper`, `.chip`, `.seg` ໃນ `css/styles.css`.

## Cloud Mode (Google Sheet) — ຍັງບໍ່ພ້ອມ

ໃສ່ URL Web App ໃນ `APPS_SCRIPT_URL` ຂອງ `js/config.js` ເພື່ອເກັບໃນ Google Sheet.
**ຍັງຂາດ**: ໂຄດ Apps Script (`Code.gs`) ຍັງບໍ່ຢູ່ໃນ repo, ແລະຍັງບໍ່ມີ login/token — ຢ່າເປີດໃຊ້ຈິງຈົນກວ່າຈະເຮັດສອງຢ່າງນີ້.
ປັດຈຸບັນ "ບົດບາດ" (Admin/Accountant/...) ແມ່ນພຽງການຊ່ອນເມນູໃນ browser, ບໍ່ແມ່ນຄວາມປອດໄພ.
